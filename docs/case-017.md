# 首案维护与试用

《消失的第 17 箱货物》是本站原创虚构案件。`src/cases/case-017.json` 包含两份单据、固定预期值、两组变式、分层提示、两种参考解法、线索和结构化结论。没有导入私人 PDF、译文或聊天记录。

案件通过 `CaseDefinition` 定义，不使用课程编号。`CalculationTask` 是课程与案件共享的最小计算接口；工作表面板、Univer 适配器、会话取消与判题 Worker 继续复用。案件单独管理线索、证据和结案，课程记录没有改变。

## 证据与存档

第一份工作簿逐箱对账，并检查总数与差额。通过后开放标签对照和临时调拨。第二份核对有效、撤回箱数及有效去向；结案还要求绑定两份当前证据。原始单据的值与表名不能改，允许在空白位置建立辅助列。两套解法都通过原始数据及两组变式，判题不比较参考公式字符串。

每次修改使当前步骤及后续证据失效，已解锁的单据仍可查看。存档记录输入公式/值的指纹，刷新时不让与草稿不一致的核验结果复活。检查沿用 PR 04 的取消、修订与超时机制。

案件使用独立 IndexedDB `supply-station-cases`，排队写入调用时的快照，并在事务内校验修订号。多标签页旧版本不能覆盖新记录。界面显示保存状态；离开前应等到“案件已保存到本机”。存储失败保留页面作答，可单独导出案件 JSON。课程 v1 备份仍只包含课程，PR 06 再做统一备份升级；此阶段案件导出用于保留和人工恢复，不宣称已有统一导入能力。

## 新手试用脚本

目标时长约 10–15 分钟，当前未做真实用户计时。参与人数：0；没有把自动化测试计作用户试用。

1. 请参与者从首页找到案件入口；不提示按钮位置，记录是否能理解 17 与 16 的差额。
2. 让参与者独立找出缺少签收的箱号。观察是否理解两张表按箱号关联、缺失返回 0、填充和合计。
3. 卡住时让其自行找提示；记录打开哪一层、是否去练习、返回是否找得到原草稿。
4. 标签单开放后，观察其能否区分有效与撤回，是否会直接把第一条去向当答案。
5. 提交交接。记录证据绑定是否容易理解、错误反馈是否帮助修正。
6. 修改已核验公式，确认参与者理解为什么需要重新核验。刷新后继续，再导出案件备份。

记录设备、浏览器、开始/结束时间、提示次数、卡点原话与实际失败步骤。真实 Excel 对照仅覆盖 PR 03 课程黄金样例；新案件公式的桌面 Excel 对照仍待验证。平板真机、原生中文输入法和读屏器仍待实测。
