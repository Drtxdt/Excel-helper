# 备份导入边界

统一导入入口继续接受 `supply-station` v1/v2。v1 只替换课程，v2 替换课程和案件。单案件入口接受 `supply-station-case` v1，复用同样的读取与工作簿边界，确认后只恢复对应案件；详见 `backup-v2.md`。

## 读取与校验顺序

文件大小预筛 → 64 KiB 分块读取与严格 UTF-8 解码 → 累计字符数检查 → JSON 解析 → 全部工作簿结构与资源计数 → 记录/案件 schema 校验 → 原有存储写入队列 → 原子备份与替换。

读取期间可以取消，离开记录页也会取消。每次最多读取一个 64 KiB 切片，取消或异常后不再读取剩余部分；在读取结束后的取消检查通过前，不调用恢复服务。进入恢复阶段后不提供取消按钮，备份和替换仍由同一 IndexedDB 事务保证一致性。直接调用字符串恢复接口也会执行字符和工作簿限制。

| 项目 | 上限 |
| --- | --- |
| UTF-8 文件 | 60,000,000 字节 |
| 解码字符串 | 20,000,000 字符（沿用 JavaScript 字符串长度，即 UTF-16 码元计数） |
| 每工作簿 | 16 张工作表 |
| 每表声明尺寸 | 2,000 行 × 128 列 |
| 每工作簿存储格 | 10,000 个 |
| 整份备份存储格 | 100,000 个，合计课程与案件各步骤 |
| 单公式 | 8,192 字符 |

存储格包含空对象和仅有样式的格子，不能靠删除值来绕过计数。坐标必须是规范的非负整数，且在声明尺寸内。工作簿及工作表 ID、工作表顺序、名称唯一性、任务必需表、行列属性索引与合并区域也会检查。拒绝时指出对应关卡/案件、工作表或具体限制；不截断、不自动修复、不写入，也不覆盖现有导入前副本。

辅助表、样式、条件格式、数据验证及其他引擎字段保留。这里检查的是本站导入结构与规模，不是 Univer 全部资源的语义审计或性能保证，也不证明导入的公式真的通过过课程判题。超限旧备份应保留原件，在原环境整理后重新导出。

2026-10-28 统计内置 40 关与首案 2 个步骤：最多 3 张表，生成尺寸 50×18，最多 112 个存储格，参考解法公式最长 48 字符。

## 回归入口

- `pnpm test tests/backup-boundaries.test.ts tests/backup-v2.test.ts tests/storage-concurrency.test.ts`：临界值与超限、UTF-8 跨切片、取消、读取异常、畸形坐标/结构、v1/v2、案件限制和写入前隔离。
- `pnpm exec playwright test e2e/backup.spec.ts e2e/backup-v2.spec.ts e2e/backup-operations.spec.ts --project=chromium`：真实文件导入导出、拒绝提示、原记录保留，以及筛选/条件格式/数据验证资源往返。
- `pnpm check`：全部课程、案件、既有 Excel 黄金样例、类型、构建及体积预算。没有重新运行真实 Excel，不扩大兼容性结论。
