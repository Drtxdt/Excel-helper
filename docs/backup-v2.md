# 统一学习备份 v2

导出格式仍为 `supply-station`，`version` 升为 2，新增 `cases`。它包含案件草稿、提示使用、已解锁步骤、证据指纹、交接选择与完成状态。导入重新验证 ID、版本、步骤和证据一致性；无效证据清除后续核验，错误结论不会保留已结案标记。

- v2 导入替换课程和案件；v1 仅替换课程，保留当前案件。
- 导入前副本与两类记录在同一 IndexedDB 事务提交。失败不留下部分恢复。
- 当前数据库继续使用 `supply-station` v1 的 `records`、`settings` 两个 store，案件存放于 `settings` 的 `case:<id>` 键。无需阻塞旧数据库连接来升级 object store。
- 同页课程、案件保存和导入共用连接/队列。案件保存调用时取得独立快照，事务检查案件修订和全局导入代次；导入后旧页面不能覆盖新记录。
- 首次读取先完整验证 PR 05 的 `supply-station-cases`，再原子写入迁移副本、案件和迁移标记。旧库保留，迁移只执行一次，之后清空案件也不会被旧库重新填回。
- 学习记录页可下载导入前、升级前两个副本。完整导出失败时明确降级为课程应急备份；调查桌仍可单独导出内存作答。

升级前请关闭仍运行 PR 05 旧代码的调查桌，再在新版打开。旧版本写入的仍是旧案件库，新版不会自动合并两份工作簿；保留旧库用于找回迁移后仍在旧页面产生的记录。统一导入入口也接受 PR 05 的 `supply-station-case` v1 文件：先展示案件名称与覆盖范围，确认后只替换对应案件。它不被伪装成空课程的完整备份。

验证包括原生 fake-indexeddb 事务中止、排队快照、跨标签页旧修订、课程/案件往返、损坏记录隔离、迁移幂等；浏览器回归通过真实导出和文件选择器恢复到新上下文。自动测试不会证明未知版本或手工篡改备份里的公式实际通过过判题；证据指纹只用于一致性，不是防作弊签名。


## 单案件恢复与故障导出

单案件文件继续使用 `{ format: "supply-station-case", version: 1, progress }`。读取限制、工作簿预检与统一备份一致；案件版本、步骤和证据通过相同的 `parseCaseProgress` 校验。证据与草稿不一致时清除相应核验状态，保留草稿供重新核验。

确认后，恢复操作等待本页已排队保存。在同一读写事务中保存完整导入前副本、更新目标案件修订、增加全局代次；不清空课程或其他案件，保留课程修订。旧标签页随后保存会因为代次/修订不符而被拒绝。同页课程内存也不被替换。取消确认不进入恢复队列；写入开始后等待事务完成，失败整体回滚。

调查桌读取进度完成前禁用导出。表格提交成功时导出当前进度；初始化不可用且没有活动编辑时，允许导出已加载/已提交的进度，并明确提示“不包含尚未提交的输入”。活动编辑被拒绝、取消或提交失败时停止导出、保留输入并说明原因。不会把失败的编辑静默省略后声称完整导出。

回归：`tests/case-backup.test.ts` 覆盖单案件往返、其他案件/课程保留、事务中止、旧标签页和排队请求；`e2e/case-backup.spec.ts` 通过真实导出与文件输入验证确认/取消/恢复，通过 Worker 构造失败仿真验证故障导出，通过漏等号输入验证提交失败不下载。故障仿真不代表真实设备故障已逐项验证。
